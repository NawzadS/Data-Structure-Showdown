For the timed challenge, I chose to use a set to keep track of the values I had already seen. I thought a set made the most sense because the main thing I needed to do was quickly check whether a value had already appeared before. As I went through the list, I checked each value against the set. If it was already there, I returned that value as the first repeated value. If it was not there, I added it to the set and continued. Since checking and adding to a set are usually O(1), the entire solution should run in O(n) time because I only need to go through the list once.

The 30 minute time limit made me focus more on getting a simple working solution instead of trying to make the code complicated. I chose a structure that I was familiar with and that clearly matched what the problem was asking for. I also spent some of the time thinking about edge cases instead of only testing the example that was given.

One trade-off with my solution is that the set uses extra memory because it stores values as I go through the list. I thought that was worth it because it prevents me from having to repeatedly search through the entire list. Under the time limit, I preferred a solution that was easy to understand, efficient, and easy for me to test.
